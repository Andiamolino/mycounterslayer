#### Tile trays

New tray type **Tile** for flat tiles and cards without a foot: one row of tiles leaning at an angle to the floor, held by two bars.

- **TILES section:** the **Dimensions** panel has a new **TILES** section to define tiles (width, height, thickness, angle to floor, slot clearance). Tiles can be exported and imported like other parts.
- **Tile tray editor:** pick the tile type and the count, and set the bar positions. The tray grows when the tiles need more room; width and length can be set as minimums.
- **Add menu:** Tile is offered when adding a tray.
- **Add menu preview:** the tray type list shows a preview of the tile tray.
- **Standee trays are now always Alternating:** the one-sided arrangement (including bar position and bar height fields) has moved to Tile trays. Older files with one-sided standee data load as a normal standee with foot; the obsolete fields are ignored.
- **Delete protection:** counters, card sizes, standees and tiles that are still in use cannot be deleted. A message lists where they are used.

#### Standee trays

Standee trays can now hold cards and tiles without a foot, standing at an angle to the floor.

- **Arrangement:** each standee has a new **Arrangement** setting. **Alternating** is the familiar layout (foot, two rows, the right row offset by half a pitch). **One-sided** is meant for cards and tiles without a foot: two bars, one row, leaning at an angle to the floor.
- **Angle to floor:** 45-90° (default 70°). It also applies to Alternating.
- **Slot clearance:** extra play added to the thickness to get the slot width (default 1 mm). The resulting **Slot width** is shown next to it.
- **Bar position left / right:** where the two bars sit, measured from the edge of the standee. Only shown and used for One-sided.
- **Bar height:** new tray field for the height of the bars (One-sided). The hint shows the maximum, which is the height of the leaning standees.
- **Tray editor fields:** clearer names and hints. One-sided trays have **Bar thickness**, **Bar height** and **Wall height above standees**; Alternating trays have **Slot wall thickness**. **Tray width** and **Tray length** are minimums, the tray grows when the standees need more.
- **Bar gap:** the real gap between the bars is now shown in the tray editor (One-sided), since it depends on the tray's bar thickness. It no longer appears in the standee definition.
- **Distribution display:** the tray editor shows how the standees are split, for example "Left 3 + right 2 = 5" for Alternating or "One row of 5" for One-sided.
- **Preview counters:** now on by default for standee trays. A manual choice applies only while the same tray stays selected; switching to another tray resets it to automatic. For One-sided, the preview shows the standees without a foot.
- **Taller trays:** One-sided trays are higher than Alternating ones. Switching the arrangement can change the box, layer and total height and the height status.
- **Export and import:** project, standee and tray files include the new fields. Older files can still be imported. The import dialog shows the slot play as "clearance".
- **Fix, custom standees in dimension displays:** custom standees are now counted in the dimensions shown in the Boxes, Trays and editor panels, Edit Layout, the layer view and the PDF layout.
- **Fix, layer arrangement:** the layer arrangement now accounts for custom standees in projects that use them. A layer can therefore change.
- **Fix, Regenerate button:** it now also lights up after changing counter, card or standee definitions.
- **Fix, invalid standee count:** an invalid Standee count is now treated as 0.
- Existing projects stay Alternating, 70°, +1 mm clearance. Their result is unchanged.

#### Game container height

The **Game Container** section has a new optional **Height** field: the inner height of your game box with the lid closed (mm, minimum 1 mm). Leave it empty to skip the height check.

- **Layer heights and total:** the navigation shows the height of each layer and, below the layer list, the total of all layers. The same total and status appear under the Height field.
- **Status:** the total is compared with the box height and reports "too tall by X mm" when the layers do not fit.
- **Layer content dimensions:** the heights shown in the layer editor now have one decimal place.
- **Free space:** when the layers fit, the status also shows how much height is left ("7.6 mm free"; "0.0 mm free" when the box is exactly full).
- **Import warning:** importing a layer that makes the layers too tall for the box shows a warning in the import preview and the result message. The import is not blocked.
- **Lid lift:** the optional **Lid lift** field next to the Height field says how far the lid may rise above the box (mm). Leave it empty or enter 0 for no lift.
- **Lift status:** when the layers are taller than the box but the lift covers the difference, the status reads "lid lifts by X mm" in its own warning color.
- **Lift is not free space:** the lift never counts as free height. Without a Height the lift has no effect.
- The height and the lid lift are saved with the project and included in JSON export and import.

#### Decimal input

- **Decimal comma accepted in all number fields:** "2,5" and "2.5" both give 2.5. The fields are now text inputs with a decimal keypad on mobile, and the spinner arrows are removed.
- **Empty or invalid input keeps the previous value:** the field is reset to the value it had before.

#### Lid thickness

Each box has a new **Lid thickness** field (next to Floor in the box panel). It sets the thickness of the lid plate in mm (default 2 mm, minimum 1.5 mm). The minimum total height of the box grows with it. If the box is raised to a taller layer, its outer height stays the same and the box body and its trays get lower instead.

#### Consistent lid and layer heights

Lid, box and layer heights now come from one calculation that matches the printed geometry.

- **Thinner lids (printed parts change):** the lid plate is now 2 mm thick by default instead of following the wall thickness (see Lid thickness). With 3 mm walls the lid is 5 mm tall instead of 6 mm (2 mm plate and 3 mm rim). The rim is unchanged. Already printed lids still fit, but newly exported lids are thinner.
- **Heights add up:** a box body plus its lid now equals the layer height shown in the app, so the layer and total heights shown drop by 4 mm with 3 mm walls (body + 2 instead of body + 6), and the sum of the layers matches the real stack. The real assembled box is only 1 mm lower (lid 5 instead of 6 mm). Boxes with a custom total height keep their body height; the shown total is lower – check it.
- **No double counting:** when a box is raised to the layer height, its trays no longer get an extra spacer on top, so they no longer stand above the box rim.
- **Standee trays:** the layer height shown in the panels now includes custom standees, as the 3D view and the exports already did.
- **Command line export:** `generate-geometry` uses the same heights as the app.
- **Minimum floor:** the Floor fields of boxes and all tray types now accept at least 1.5 mm. Smaller input is raised to 1.5 mm; existing projects are not changed when loaded.
- **Layer content dimensions:** the tray height shown in the layer editor now subtracts the lid as well, for example, a 27 mm layer with 2 mm floor and 2 mm lid now shows 23 mm instead of 25 mm.

#### Part library

Export single parts to a file and import them into any other project. Counters, card sizes, standees, trays, boxes and whole layers each have their own file type (`.counter.json`, `.card.json`, `.standee.json`, `.tray.json`, `.box.json` and `.layer.json`).

- **Export:** counters, card sizes and standees have an **Export** button next to them in the Dimensions panel. Trays, boxes and layers are exported with the **Export** button in the bottom bar of their editor. The file is named after the part.
- **Import:** counters, card sizes and standees are imported with the **Import…** buttons in the Dimensions panel. Trays, boxes and layers are imported with **Import from file…** in the matching **Add** menu, so the part lands exactly where you add it. A preview dialog shows what will be added before anything changes.
- **Dependencies come along:** a tray, box or layer brings the counters, card sizes and standees it uses.
- **No duplicates:** a counter, card size or standee with the same name and the same values is reused. If the name is taken by something different, the import is added as "Name (2)", "Name (3)" and so on. Trays, boxes and layers are always added as new items and renamed the same way if needed.
- **Safe imports:** if a file refers to something it does not contain, the import is cancelled and your project stays untouched. A box or layer that is larger than the game container is still imported and you get a warning, positions are kept.
- **Right place, right button:** a part file loaded through "Import project JSON" is rejected with a hint, and your project is not changed.

#### Project name

Projects now have a name. It shows in the header and in the browser tab, and you can change it by clicking it or in the **Project** section of the Dimensions panel. New projects start as "Untitled Project".

- **Export:** exporting the project JSON asks for a file name, pre-filled with the project name. Characters that are not allowed in file names are replaced with "-". The STL ZIP, 3MF and PDF downloads are named after the project too.
- **Import:** a project file without a name uses its file name, and community projects use the name from their manifest.
